Documentação Técnica — LOGIEXPRESS 1.1

Guia prático para entender a aplicação existente e saber onde alterar ou criar código durante os exercícios.

Objetivo: entender o caminho HTML → Flask → banco → Flask → Jinja2 → HTML antes de começar uma nova funcionalidade. O aluno deve aproveitar os padrões já existentes no LOGIEXPRESS.

1. Visão geral da arquitetura

O navegador envia uma requisição HTTP. O Flask recebe essa requisição por uma rota, executa a regra necessária, consulta ou altera os dados usando SQLAlchemy e, quando precisa exibir uma página, envia os dados para um template Jinja2.

3. app.py — o centro do backend

O app.py cria o Flask, configura o banco, define os modelos, registra as rotas, executa consultas e alterações e envia dados aos templates.

🔎 Abrir imagem explicativa do app.py
Flask: app = Flask(__name__) cria a aplicação.
SQLAlchemy: db = SQLAlchemy(app) permite trabalhar com o banco por Python.
GET: normalmente consulta ou exibe dados.
POST: recebe dados enviados pelo formulário para processamento.

Como os dados chegam ao HTML?

clientes = Cliente.query.order_by(Cliente.id.desc()).all()

return render_template(
    "clientes/list.html",
    clientes=clientes
)

A variável clientes é enviada pelo render_template(). O Jinja2 usa essa variável para gerar o HTML da lista.

Como as tabelas são criadas?

with app.app_context():
    db.create_all()
    seed_data()
  • db.create_all() cria as tabelas definidas pelos modelos quando ainda não existem.
  • seed_data() cria registros iniciais para demonstrar o sistema.
  • No projeto atual, a carga inicial começa verificando se já existe um cliente.

Como os dados são enviados para uma página?

clientes = Cliente.query.order_by(Cliente.id.desc()).all()

return render_template(
    "clientes/list.html",
    clientes=clientes
)

O GET chama a rota de consulta. A consulta retorna objetos Python. O render_template() recebe esses objetos como variáveis e o Jinja2 os transforma em HTML.

O que o aluno precisará alterar?

  1. Se o exercício precisar de uma nova entidade, crie um novo modelo seguindo o padrão existente.
  2. Defina os campos e, se necessário, os relacionamentos.
  3. Crie as rotas que consultarão ou alterarão esse modelo.
  4. Crie os templates que apresentarão os dados.
  5. Adicione carga inicial somente se ela for útil para o exercício.

6. Regra de negócio da exclusão

O sistema não permite excluir um cliente que possui pedidos relacionados.

quantidade_pedidos = Pedido.query.filter_by(
    cliente_id=cliente.id
).count()

if quantidade_pedidos > 0:
    flash(
        "Não é possível excluir este cliente...",
        "warning"
    )

Em um novo exercício, procure também identificar regras desse tipo: o sistema deve aceitar qualquer alteração ou existe uma condição que precisa ser validada?

8. Jinja2 — o que é, por que usamos e como alterar

O que é? Jinja2 é o mecanismo de templates usado pelo Flask para gerar HTML dinamicamente. O Python envia dados e o Jinja2 utiliza esses dados dentro do HTML.

Por que usamos?

  • separa lógica Python da apresentação HTML;
  • permite reutilizar o layout com base.html;
  • permite percorrer listas vindas do banco;
  • permite condições, links e valores dinâmicos.

Exemplo 1 — variável

{% raw %}{{ cliente.nome }}{% endraw %}

Isso só funciona se a rota enviar uma variável chamada cliente.

Exemplo 2 — repetição

{% raw %}{% for cliente in clientes %}

    {{ cliente.id }}
    {{ cliente.nome }}
    {{ cliente.cidade }} / {{ cliente.uf }}

{% endfor %}{% endraw %}

Exemplo 3 — condição

{% raw %}{% if cliente.ativo %}
    Ativo
{% else %}
    Inativo
{% endif %}{% endraw %}

Exemplo 4 — link para uma rota Flask

{% raw %}<a href="{{ url_for('clientes_editar', cliente_id=cliente.id) }}">Editar</a>{% endraw %}

No exemplo acima, o código está sendo demonstrado e não é um link da própria documentação. Para testar uma rota real, use o botão abaixo.

🔗 Abrir exemplo real — editar Cliente 1

Como alterar ou criar?

  1. Veja qual variável o render_template() envia.
  2. Use exatamente o mesmo nome no template.
  3. Se criar um campo novo, ele precisa existir no modelo e ser tratado pela rota quando necessário.
  4. Depois altere o HTML/Jinja2 para apresentar o campo.
  5. Teste no navegador antes do commit.
Erro comum: escrever {{ novo_campo }} no HTML sem criar/consultar esse dado no Python. O template depende das variáveis enviadas pela rota.
Exemplo: se sua rota envia veiculos=veiculos, o template pode usar {% raw %}{% for veiculo in veiculos %}{% endraw %}. Não invente o nome da variável: confira o render_template().

9. O que o aluno deve criar ou alterar no exercício?

O objetivo é evoluir o LOGIEXPRESS, não reconstruí-lo. Use um módulo existente como referência.

  1. Leia o requisito do desafio.
  2. Escolha um módulo semelhante como referência.
  3. Crie/altere o modelo de dados se necessário.
  4. Crie as rotas GET/POST necessárias.
  1. Crie/duplique e adapte os templates.
  2. Ajuste CSS/menu somente quando necessário.
  3. Teste a funcionalidade completa.
  4. Commit → push → Pull Request.
Checklist: Modelo → Rotas → Banco → Template → Jinja2 → CSS/menu → Teste → Commit → Push → Pull Request.

10. GET/POST da aplicação × push do Git

Não confunda os dois conceitos: GET e POST são métodos HTTP usados pela aplicação; push é um comando do Git para enviar os commits da sua branch ao GitHub. 

git checkout -b feature/minha-funcionalidade
# desenvolver e testar
git add .
git commit -m "Implementa minha funcionalidade"
git push -u origin feature/minha-funcionalidade

Depois do push, o grupo abre o Pull Request para solicitar a integração da alteração.
