RAD significa Desenvolvimento Rápido de Aplicações. É uma abordagem que privilegia ciclos curtos de desenvolvimento, prototipação, testes e retorno dos usuários.

{{ imagem('RAD — construir, testar e evoluir', [ ('REQUISITO','O que precisa','ser resolvido'), ('DESENVOLVIMENTO','Construir uma','primeira solução'), ('TESTE','Executar e','encontrar problemas'), ('FEEDBACK','Aprender e','melhorar') ], 'O ciclo se repete: a aplicação evolui em pequenas entregas.') }}
Contexto no LOGIEXPRESS

Você não começará um sistema do zero. O LOGIEXPRESS já possui banco, telas, rotas, dashboard e CRUD. A atividade consiste em compreender a base e evoluí-la com novas funcionalidades.

  • receber um requisito;
  • entender o código existente;
  • implementar uma pequena evolução;
  • testar no navegador;
  • registrar a alteração no Git;
  • enviar a alteração para revisão por Pull Request.
Ideia principal: RAD não significa fazer de qualquer jeito. Significa aprender rapidamente com ciclos curtos e controlados.

Python é a linguagem utilizada no backend do LOGIEXPRESS. É nela que estão as regras de negócio, consultas ao banco, tratamento dos formulários e preparação dos dados que serão apresentados.

{{ imagem('Python no LOGIEXPRESS', [ ('ENTRADA','request HTTP','formulário'), ('PYTHON','rota + lógica','validação'), ('DADOS','consulta ou','alteração'), ('SAÍDA','template','HTML') ], 'O Python funciona como a camada que coordena o processamento da aplicação.') }}
Onde procurar no projeto?

O principal arquivo é app.py. Procure por app = Flask(__name__), pelos modelos db.Model e pelas funções decoradas com @app.route().

Exemplo
clientes = Cliente.query.order_by(Cliente.id.desc()).all()
return render_template("clientes/list.html", clientes=clientes)

Neste exemplo, Python consulta o banco e envia o resultado para o template.

Flask é o framework web usado para transformar Python em uma aplicação acessível pelo navegador. Ele recebe requisições HTTP, identifica a rota correspondente e executa a função definida pelo desenvolvedor.

{{ imagem('Flask conecta URL, função e resposta', [ ('NAVEGADOR','GET /clientes','ou POST'), ('ROTA','@app.route','define o caminho'), ('FUNÇÃO','Python','processa'), ('RESPOSTA','HTML / redirect','retorna') ], 'A rota é a porta de entrada para uma funcionalidade web.') }}
Exemplo real
@app.route("/clientes")
def clientes_list():
    clientes = Cliente.query.order_by(Cliente.id.desc()).all()
    return render_template("clientes/list.html", clientes=clientes)

Quando o navegador solicita /clientes, Flask encontra clientes_list(). A função consulta os dados e retorna a página.

Para o exercício: antes de criar uma rota nova, procure uma rota existente que faça algo parecido.

Git é um sistema de controle de versão. Ele registra a evolução do código e permite saber quais alterações foram feitas, quando foram feitas e em qual sequência.

{{ imagem('Git registra a evolução do código', [ ('ARQUIVOS','alteração','no projeto'), ('STAGE','git add','prepara'), ('COMMIT','git commit','registra'), ('HISTÓRICO','versões','recuperáveis') ], 'Git não é o GitHub: Git controla versões; GitHub hospeda e colabora sobre o repositório.') }}
Por que isso importa na aula?

Como vários grupos desenvolverão funcionalidades diferentes, precisamos de um histórico organizado. O Git permite separar trabalhos, comparar alterações e recuperar versões.

git status
git add .
git commit -m "feat: adiciona controle de manutenção"

Regra prática: faça commits pequenos e coerentes. Um commit deve representar uma alteração que faça sentido explicar para outra pessoa.

GitHub é a plataforma onde o repositório do LOGIEXPRESS está hospedado. Ele permite compartilhar o código, trabalhar com branches, Issues, Pull Requests e acompanhar a evolução do projeto.

{{ imagem('GitHub como ponto de colaboração', [ ('REPOSITÓRIO','código','central'), ('BRANCHES','trabalhos','isolados'), ('ISSUES','tarefas','requisitos'), ('PR','revisão','integração') ], 'No projeto, o GitHub é o ambiente de colaboração entre os grupos.') }}
GitHub no LOGIEXPRESS

O repositório contém o código que os alunos acessam pelo Codespaces. A branch de cada grupo será usada para desenvolver uma funcionalidade sem trabalhar diretamente na versão principal.

Atenção: GitHub não substitui o Git. O Git registra as versões localmente; o GitHub permite armazenar, compartilhar e colaborar sobre esse histórico.

GitHub Codespaces é um ambiente de desenvolvimento hospedado na nuvem. O aluno acessa o projeto pelo navegador e recebe um ambiente com editor, terminal e recursos para executar a aplicação.

{{ imagem('Codespaces — desenvolvimento no navegador', [ ('GITHUB','repositório','do projeto'), ('CODESPACE','VS Code Web','+ terminal'), ('PYTHON','executa','Flask'), ('NAVEGADOR','acessa a','aplicação') ], 'O ambiente reduz a necessidade de configurar Python, banco e ferramentas manualmente no computador.') }}
O que você verá?
  • Explorer: arquivos do projeto;
  • Editor: local para alterar o código;
  • Terminal: execução de comandos Git e Python;
  • Portas: acesso à aplicação que está rodando.

Objetivo pedagógico: concentrar a aula no desenvolvimento da aplicação, e não na configuração da máquina.

Uma branch é uma linha independente de desenvolvimento. Ela permite que uma funcionalidade seja desenvolvida sem alterar diretamente a branch que representa a versão integrada.

{{ imagem('Branches isolam os trabalhos', [ ('main','versão','estável'), ('develop','integração','das equipes'), ('feature','funcionalidade','do grupo'), ('PR','revisão','e integração') ], 'Cada grupo desenvolve sua funcionalidade em uma branch própria.') }}
Exemplo utilizado na prática
main
  ↓
develop
  ↓
feature/manutencao-veiculos

O grupo pode trabalhar, testar e fazer vários commits na sua branch. Quando terminar, envia a branch ao GitHub e abre um Pull Request para integração.

Boa prática: o nome da branch deve deixar claro qual funcionalidade está sendo desenvolvida.

Commit é um registro permanente de uma alteração no histórico Git. Pense nele como uma fotografia identificada do estado do código naquele momento.

{{ imagem('Commit — ponto de controle do projeto', [ ('ANTES','código','anterior'), ('ALTERAÇÃO','arquivos','modificados'), ('COMMIT','mensagem','descritiva'), ('HISTÓRICO','ponto','recuperável') ], 'Commits bem descritos facilitam revisão, rastreamento e recuperação.') }}
Exemplo
git add .
git commit -m "feat: adiciona controle de manutenção"

Evite mensagens como teste, alterações ou coisas. Prefira uma mensagem que explique a mudança.

Importante: commit ainda não significa que o código foi enviado ao GitHub. Para isso existe o git push.

Pull Request (PR) é uma solicitação para integrar o trabalho de uma branch em outra. Além de integrar código, o PR cria um ponto de revisão e discussão.

{{ imagem('Pull Request — da funcionalidade à integração', [ ('FEATURE','grupo','desenvolve'), ('PUSH','branch','no GitHub'), ('PR','comparar','e revisar'), ('MERGE','integrar','em develop') ], 'O PR funciona como uma etapa de controle antes da integração.') }}
Fluxo da atividade
  1. criar branch da funcionalidade;
  2. desenvolver;
  3. testar;
  4. commit;
  5. push;
  6. abrir Pull Request;
  7. revisar;
  8. integrar.
Não abra o PR apenas porque o código roda. Verifique também requisito, interface, dados, mensagens de erro e comportamento esperado.

SQLite é um banco de dados relacional que pode ser armazenado em um arquivo. No ambiente local do LOGIEXPRESS, ele permite que os alunos executem a aplicação sem instalar um servidor de banco separado.

{{ imagem('SQLite no ambiente de desenvolvimento', [ ('FLASK','aplicação','Python'), ('SQLALCHEMY','ORM','consultas'), ('SQLITE','arquivo','logiexpress.db'), ('DADOS','tabelas','registros') ], 'SQLite é adequado para o ambiente didático local; a configuração de produção usa PostgreSQL.') }}
O que existe dentro?

O banco possui tabelas correspondentes aos modelos, como Clientes, Pedidos, Entregas, Veículos, Produtos e Ocorrências.

O aluno normalmente não precisa abrir o arquivo do banco manualmente. As consultas são feitas pelo SQLAlchemy no código Python.

SQLAlchemy é a biblioteca utilizada para trabalhar com o banco de dados a partir do Python. O LOGIEXPRESS utiliza seu recurso ORM, no qual modelos Python representam tabelas.

{{ imagem('SQLAlchemy faz a ponte entre Python e banco', [ ('PYTHON','Cliente','Pedido'), ('ORM','Modelos +','queries'), ('BANCO','tabelas','registros'), ('RESULTADO','objetos','Python') ], 'O ORM permite que o código trabalhe com os dados sem escrever SQL manualmente em cada operação.') }}
Exemplo
clientes = Cliente.query.filter_by(ativo=True).all()

db.session.add(cliente)
db.session.commit()

query consulta. filter_by aplica um filtro. add prepara um novo registro para gravação. commit confirma a transação.

Para o aluno: não é necessário dominar SQLAlchemy inteiro. Aprenda a reconhecer os padrões já usados no projeto e adaptá-los.

CRUD representa quatro operações básicas sobre dados: Create, Read, Update e Delete.

{{ imagem('CRUD — ciclo básico de um cadastro', [ ('CREATE','criar','registro'), ('READ','consultar','registro'), ('UPDATE','alterar','registro'), ('DELETE','excluir','registro') ], 'O CRUD de Clientes é o exemplo de referência do LOGIEXPRESS.') }}
OperaçãoExemploNo LOGIEXPRESS
CreateCadastrar cliente/clientes/novo
ReadListar cliente/clientes
UpdateEditar cliente/clientes/<id>/editar
DeleteExcluir cliente/clientes/<id>/excluir

Importante: CRUD não significa que toda exclusão deve ser permitida. O sistema pode possuir regras de negócio, como a regra que impede excluir cliente com pedidos relacionados.

HTTP é o protocolo utilizado para comunicação entre navegador e aplicação web. No LOGIEXPRESS, os métodos que mais aparecerão nos exercícios são GET e POST.

{{ imagem('GET e POST têm papéis diferentes', [ ('GET','pedir','uma página/dados'), ('FORM','usuário','preenche'), ('POST','enviar','dados'), ('FLASK','validar','e processar') ], 'GET costuma consultar/exibir; POST costuma enviar dados para processamento.') }}
Exemplo
@app.route("/clientes/novo", methods=["GET", "POST"])
def clientes_novo():
    if request.method == "POST":
        ...
    return render_template("clientes/form.html")

Na primeira visita, GET exibe o formulário. Depois que o usuário envia, POST entrega os dados para a função.

Não confunda: HTTP POST envia dados para a aplicação. git push envia commits para o repositório remoto.
